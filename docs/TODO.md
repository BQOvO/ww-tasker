# 鸣潮地区任务查漏补缺 · 待办

## 现在能用的

- 三态打勾（未开始 / 进行中 / 已完成），点圆圈就换一档
- 每条任务可以写一行备注
- **23 个版本 / 335 条真实任务**（数据来自 B 站「叫我棉被」的全任务攻略合集）
- 左列按版本平铺（1.0 到 3.8 能滚），右列按任务类型分页签（含「活动」）
- 「隐藏做完的版本」筛选：整版都勾完了就从左列消失（正选着的那条留着自己）
- 左列进度 x/y + 进度条，底部「全部」汇总
- 「只看未完成」筛选
- 折叠成 236×30 的细条
- 默认窗口 392×440（0.6.0 从 632 减了近三分之一，老存档会自动跟着换）
- 透明度 30%–100%（面板底变淡，字始终实色）
- 点击穿透（锁定）
- 全局快捷键，三个都能在设置里改
- 多个存档，能新建 / 改名 / 删除
- 任务库从仓库拉更新、程序自己查新版
- 自己的图标（exe 资源、窗口、任务栏都是它），7 帧 ico 从 16 到 256
- 右键任务能直接跳到对应的 B 站分 P 攻略

## 已知限制

- **独占全屏看不见**。Windows 上任何悬浮窗都画不出来，只能让游戏跑无边框窗口 / 窗口化全屏
- 存档只记任务 id 不记名字，所以 id 不能改（改了等于那条进度丢了）
- 检查更新是同步 HTTP，网络卡的时候会顿一下（在后台线程，不冻 UI）
- `softprops/action-gh-release` 撞到已存在的 release 时只补 asset 不更新正文，
  所以要重发一次更新日志得手动 dispatch（tag 没变的话）
- 0.1.0 的占位任务（id 形如 `jz.main.01`）和 0.4.0 以前的库街区那条线都作废了，
  `schemaVersion` 涨到 3（按版本分组）时整份换掉、不做合并
- 窗口尺寸记在存档里，改默认值只对新用户生效。所以 `settings.layoutVersion` 就是干这个的：
  改一次默认尺寸就 +1，老存档读到之后尺寸和位置一起回到新默认
